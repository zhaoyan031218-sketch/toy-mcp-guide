1. 整体架构总览

本系统提供两条独立的 MCP 控制链路，分别应对不同蓝牙协议类型的玩具：

┌──────────────────────────────────────────────────────────────┐ │ RikkaHub (AI) │ │ toy_set_strength(50) / toy_stop() │ └─────────────┬────────────────────────────┬───────────────────┘ │ │ 方案一: ToyMCP 方案二: ToyADB 标准 BLE 玩具 私有协议 BLE 玩具 │ │ VPS :8897 (FastMCP) 笔记本 :8893 (FastMCP) state.json 状态文件 │ │ ADB 无线 / Tailscale 手机 Chrome 打开 HTML │ Web Bluetooth API 手机官方 APP │ ADB input swipe 模拟触摸 直接发送 BLE 指令 │ │ APP → BLE 私有协议 ┌────────┴────────┐ ┌────┴────┐ │ Erica / FenXin │ │ B220 │ │ (Svakom 协议) │ │(私有协议)│ └─────────────────┘ └─────────┘
设计原则：两条链路完全隔离，互不干扰。各自有独立的 MCP 端口、进程和 systemd 守护。

3. 方案一：ToyMCP — VPS + Web Bluetooth

VPS 标准 BLE 协议

3.1 架构与原理

RikkaHub MCP 工具调用 ↓ Streamable HTTP (带 Session ID) VPS ToyMCP 服务 (FastMCP, port 8897) ↓ 写入 state.json 手机 Chrome HTML 页轮询 ↓ 检测 state 变化 Web Bluetooth API → BLE GATT writeValue() ↓ 玩具马达

关键设计：VPS 不直接控制蓝牙——它只负责维护一个状态文件。手机上的 HTML 页面每 1 秒轮询这个文件，检测到变化后通过 Web Bluetooth API 向设备发送 BLE 指令。这样就绕过了「服务器没法直接操作蓝牙」的限制。

3.2 VPS 端：ToyMCP 服务

创建 /opt/toy-mcp/server.py：

#!/usr/bin/env python3
"""ToyMCP v3: Standard BLE toy control via FastMCP + Streamable HTTP."""
import json, os, time
from mcp.server.fastmcp import FastMCP

STATE_FILE = "/opt/toy-web/state.json"
PORT = 8897

if not os.path.exists(STATE_FILE):
    with open(STATE_FILE, "w") as f:
        json.dump({"cmd": "stop", "mode": 0, "intensity": 0, "updated_at": 0}, f)

def _write_state(cmd: str, mode: int = 0, intensity: int = 0) -> None:
    with open(STATE_FILE, "w") as f:
        json.dump({
            "cmd": cmd, "mode": mode, "intensity": intensity,
            "updated_at": int(time.time() * 1000),
        }, f)

mcp = FastMCP("toy-mcp", host="0.0.0.0", port=PORT, streamable_http_path="/")

@mcp.tool()
def toy_scan() -> str:
    """List available toys."""
    return json.dumps({"toys": [{"name": "YourToy", "index": 0}]})

@mcp.tool()
def toy_connect(index: int = 0) -> str:
    """Connect to a toy by index."""
    return json.dumps({"status": "connected", "device": "YourToy", "index": index})

@mcp.tool()
def toy_set_strength(value: float) -> str:
    """Set vibration strength 0-100."""
    val = max(0, min(100, value))
    _write_state("set", mode=1, intensity=val)
    return json.dumps({"status": "ok", "strength": val})

@mcp.tool()
def toy_stop() -> str:
    """Stop all vibration."""
    _write_state("stop")
    return json.dumps({"status": "stopped"})

@mcp.tool()
def toy_disconnect() -> str:
    """Disconnect."""
    _write_state("stop")
    return json.dumps({"status": "disconnected"})

if __name__ == "__main__":
    mcp.run(transport="streamable-http")

设计要点： streamable_http_path="/" 让 MCP 端点直接在根路径，与旧版 HTTP 服务器兼容。 intensity 存储的是原始 0-100 值（非 mapped level），留给手机 HTML 做最终的 BLE 强度映射。

将以下 HTML 部署到 VPS 的 /opt/toy-web/index.html（或 Nginx 静态目录），手机 Chrome 打开即可：

<h1 id="status">点击「扫描」连接设备</h1>
<button id="scanBtn" style="padding:16px 32px;font-size:18px;

</button>

<script>
const STATE_URL = 'http://YOUR_VPS_IP:8896/state';
window.devices = [];
let lastUpdatedAt = 0;

/* Map 0-100 strength to BLE intensity (0-255) with perceptible steps */
function mapIntensity(v) {
    if (v <= 0) return 0;
    if (v <= 20) return 50;   // gentle
    if (v <= 40) return 100;  // moderate
    if (v <= 60) return 160;  // strong
    if (v <= 80) return 210;  // very strong
    return 255;               // maximum
}

async function sendAll(intensity) {
    const i = mapIntensity(intensity);
    /* Svakom protocol: CMD 0x55 0x04, mode 0x01, intensity byte, end byte 0xAA */
    const data = new Uint8Array([0x55, 0x04, 0x00, 0x00, 0x01, i, 0xAA]);
    for (const d of window.devices) {
        try { await d.writeChar.writeValue(data); } catch(e) {}
    }
}
async function stopAll() {
    const data = new Uint8Array([0x55, 0x04, 0x00, 0x00, 0x00, 0x00, 0xAA]);
    for (const d of window.devices) {
        try { await d.writeChar.writeValue(data); } catch(e) {}
    }
}

async function connectOne() {
    document.getElementById('status').textContent = '扫描中...';
    const device = await navigator.bluetooth.requestDevice({
        acceptAllDevices: true,
        optionalServices: ['0000ffe0-0000-1000-8000-00805f9b34fb']
    });
    const server = await device.gatt.connect();
    const service = await server.getPrimaryService('0000ffe0-0000-1000-8000-00805f9b34fb');
    const chars = await service.getCharacteristics();
    let wc = null;
    for (const c of chars) {
        if (c.properties.writeWithoutResponse || c.properties.write) {
            wc = c; break;
        }
    }
    const entry = { name: device.name, writeChar: wc, device };
    window.devices.push(entry);
    device.addEventListener('gattserverdisconnected', () => {
        window.devices = window.devices.filter(d => d.device !== device);
        updateUI();
    });
    updateUI();
}

function updateUI() {
    const n = window.devices.length;
    document.getElementById('status').textContent =
        n > 0 ? '已连接 ' + n + ' 个设备' : '全部断开 - 点击重连';
    document.getElementById('status').style.color = n > 0 ? '#7ec87e' : '#f5c6a0';
}

document.getElementById('scanBtn').addEventListener('click', connectOne);

let lastCmd = null;
setInterval(async () => {
    if (window.devices.length === 0) return;
    try {
        const res = await fetch(STATE_URL);
        const state = await res.json();
        if (state.updated_at > lastUpdatedAt) {
            lastUpdatedAt = state.updated_at;
            if (state.cmd === 'stop') { lastCmd = null; await stopAll(); }
            else if (state.cmd === 'set') {
                lastCmd = state.intensity || 0;
                await sendAll(lastCmd);
            }
        }
    } catch(e) {}
}, 1000);

/* Periodic keep-alive resend */
setInterval(async () => {
    if (lastCmd !== null && window.devices.length > 0) {
        await sendAll(lastCmd);
    }
}, 1400);

if ('serviceWorker' in navigator) {
    navigator.serviceWorker.register('sw.js');
}
</script>
</body>
</html>
⚠️ HTTPS 注意： Web Bluetooth API 要求页面通过 HTTPS 访问（localhost 除外）。 如果 VPS 通过 Tailscale 暴露，可以用 tailscale serve 提供 TLS 证书； 或者手机 Chrome 访问 http://<vps_lan_ip>:8895/（局域网 HTTP 对 Bluetooth 可用）。
多设备支持： 页面支持连接多个玩具。每个设备独立 BLE GATT 连接，收到强度指令时同时向所有已连接设备发送。

3.5 强度映射问题与修复

现象：AI 调用 toy_set_strength(10) 和 toy_set_strength(100) 体感无区别。

根因：VPS 端曾将 0-100 映射为 level 1-5 再存 state.json，HTML 再将 1-5 线性映射到 0-255（1→3, 5→13），差异仅 10 个 BLE 单位，马达驱动无感知。

修复：

  1. VPS 端存储原始 0-100 值到 state.json
  2. HTML 端使用分段映射：0→0, 1-20→50, 21-40→100, 41-60→160, 61-80→210, 81-100→255
  3. 10% → BLE 50，100% → BLE 255，差异 205 个单位，体感显著

4. 方案二：ToyADB — 笔记本 ADB 触控模拟

笔记本 私有 BLE 协议

4.1 架构与原理

RikkaHub MCP 工具调用 ↓ Streamable HTTP 笔记本 ToyADB 服务 (FastMCP, port 8893) ↓ ADB 无线 (LAN 或 Tailscale) 手机 ADB 服务 ↓ adb shell input swipe X Y X Y 玩具官方 APP（界面显示滑块） ↓ APP 内置 BLE 私有协议 玩具马达

核心思路：不对私有 BLE 协议进行逆向，而是通过 ADB 模拟手指在官方 APP 上滑动强度条，让 APP 替我们发送正确的 BLE 指令。

4.2 手机端准备

  1. 打开 开发者选项：设置 → 关于手机 → 连点 MIUI 版本号 7 次
  2. 开启 USB 调试
  3. 开启 USB 调试（安全设置）——小米/HyperOS 必备，否则 ADB input 会被拦截
  4. 安装玩具官方 APP，打开并确认强度调节滑条正常显示
  5. USB 线连接笔记本一次，手机上弹窗勾选「一律允许」并确认
  6. 笔记本执行 adb tcpip 5555 开启 WiFi ADB 模式
  7. 此后拔掉 USB，全程走 WiFi

取滑条坐标：在 APP 滑条界面上，用 ADB 截图或用触控位置开发者选项确定 0% 和 100% 对应的屏幕 Y 坐标。

# 滑条坐标示例（需根据具体设备和 APP 实测校准）
0%   → Y = 1605（低端）
100% → Y = 967 （高端）
范围 638 像素，X 中心 ≈ 600

4.3 笔记本端：ToyADB 服务

安装依赖：

sudo apt-get install adb
pip3 install mcp uvicorn --break-system-packages

创建 /home/<user>/toyadb_server.py：

#!/usr/bin/env python3
"""ToyADB MCP: Control proprietary BLE toy via ADB touch simulation."""
import json, subprocess, time
from mcp.server.fastmcp import FastMCP

PORT = 8893
Y_MIN = 967   # 100% = top
Y_MAX = 1605  # 0%   = bottom
X_CENTER = 600
PHONE_LAN = "192.168.x.x:5555"        # 局域网 IP
PHONE_TAILSCALE = "100.x.x.x:5555"    # Tailscale IP (外出时)

_last_xiaomi_unblocked = False

def _adb_device() -> str | None:
    """Get ADB device, preferring WiFi. Auto-reconnect on drop."""
    try:
        result = subprocess.run(
            ["adb", "devices"], capture_output=True, text=True, timeout=5)
        wifi_device = None
        usb_device = None
        for line in result.stdout.strip().split("\n")[1:]:
            if "\tdevice" not in line: continue
            serial = line.split("\t")[0]
            if ":" in serial: wifi_device = serial
            else: usb_device = serial

        # WiFi gone but USB present → re-enable TCP mode
        if not wifi_device and usb_device:
            subprocess.run(["adb", "-s", usb_device, "tcpip", "5555"],
                           capture_output=True, text=True, timeout=8)
            time.sleep(1)
            for addr in [PHONE_LAN, PHONE_TAILSCALE]:
                subprocess.run(["adb", "connect", addr],
                               capture_output=True, text=True, timeout=5)

        # Completely gone → try reconnect
        if not wifi_device:
            for addr in [PHONE_LAN, PHONE_TAILSCALE]:
                subprocess.run(["adb", "connect", addr],
                               capture_output=True, text=True, timeout=5)

        return wifi_device or usb_device
    except Exception:
        return None

def _ensure_xiaomi_unblocked() -> None:
    """Disable HyperOS touch blocking."""
    global _last_xiaomi_unblocked
    if _last_xiaomi_unblocked: return
    device = _adb_device()
    if not device: return
    subprocess.run(["adb", "-s", device, "shell", "settings",
                    "put", "global", "block_untrusted_touches", "0"],
                   capture_output=True, text=True, timeout=5)
    _last_xiaomi_unblocked = True

def _strength_to_y(value: float) -> int:
    v = max(0, min(100, value))
    return Y_MAX - int(v / 100.0 * (Y_MAX - Y_MIN))

def _adb_tap(y_target: int) -> bool:
    device = _adb_device()
    if not device: return False
    _ensure_xiaomi_unblocked()
    x, dur = X_CENTER, 100
    r = subprocess.run(
        ["adb", "-s", device, "shell", "input", "swipe",
         str(x), str(y_target), str(x), str(y_target), str(dur)],
        capture_output=True, text=True, timeout=10)
    return r.returncode == 0

mcp = FastMCP("toyadb", host="0.0.0.0", port=PORT, streamable_http_path="/")

@mcp.tool()
def toyadb_status() -> str:
    """Check ADB connection status."""
    d = _adb_device()
    return json.dumps({"connected": bool(d), "device": d or "none"})

@mcp.tool()
def toyadb_set_strength(value: float) -> str:
    """Set strength 0-100 via ADB touch on official app."""
    y = _strength_to_y(value)
    ok = _adb_tap(y)
    return json.dumps({"status": "ok" if ok else "error",
                       "strength": value, "y_target": y})

@mcp.tool()
def toyadb_stop() -> str:
    """Stop vibration (tap bottom = 0%)."""
    _adb_tap(Y_MAX)
    return json.dumps({"status": "stopped"})

@mcp.tool()
def toyadb_mode(mode_name: str) -> str:
    """Switch mode: A (伸缩), B (吮吸), C (震动). Coordinates may need calibration."""
    modes = {"A": (200, 2050), "B": (540, 2050), "C": (880, 2050)}
    m = mode_name.upper().strip()
    if m not in modes:
        return json.dumps({"status": "error", "message": f"Unknown mode '{m}'. Use A/B/C."})
    device = _adb_device()
    x, y = modes[m]
    subprocess.run(["adb", "-s", device, "shell", "input", "tap",
                    str(x), str(y)], capture_output=True, text=True, timeout=5)
    return json.dumps({"status": "ok", "mode": m})

if __name__ == "__main__":
    mcp.run(transport="streamable-http")

4.4 Tailscale 远程连接

手机和笔记本都安装 Tailscale 后，ADB 可通过 Tailscale IP 直连：

adb connect 100.x.x.x:5555   # 手机 Tailscale IP

当手机离开家庭 WiFi 时，服务端自动尝试 Tailscale 地址作为备用通道。

4.5 Xiaomi HyperOS 特别处理

HyperOS 默认拦截 ADB 输入事件，需要：

  1. 开发者选项 → 打开 USB 调试（安全设置）
  2. 服务端启动时自动执行：adb shell settings put global block_untrusted_touches 0
注意： 手机重启后 WiFi ADB 模式会丢失。如果手机重启了，需要重新插 USB 一次， 笔记本会自动检测 USB 连接并执行 adb tcpip 5555 恢复 WiFi 模式，无需手动敲命令。

6. 常见问题

Q: MCP 报 "Session not found" 怎么办？

服务重启后会话 ID 失效是正常的。FastMCP 的会话是内存存储，重启即清空。客户端（RikkaHub）检测到这个错误会自动重新 initialize 获取新 session ID。如果没自动恢复，在 RikkaHub 里手动刷新/重连该 MCP 源即可。

Q: Streamable HTTP vs 普通 HTTP 有什么区别？

旧版 MCP 服务使用 Python http.server（HTTP/1.0），每次请求新建连接，不返回 Mcp-Session-Id。FastMCP + Streamable HTTP 使用 uvicorn（HTTP/1.1 + keep-alive），返回会话 ID，客户端初始化一次即可复用。这就是为什么升级前 RikkaHub 频繁重新初始化。

Q: 为什么方案一要在 state.json 存原始 0-100 而不是 level 1-5？

手机 HTML 需要原始值来精确映射到 BLE 0-255 范围。如果 VPS 端先做了 coarser 映射（1-5），HTML 再映射一次（1→3, 5→13），两次量化导致差异极小，马达无法区分 10% 和 100%。

Q: 如何校准 B220 的滑条坐标？

  1. 打开官方 APP，进入强度调节界面
  2. 开启「开发者选项 → 指针位置」显示触控坐标
  3. 手指触摸滑块最低端 → 记录 Y 值
  4. 手指触摸滑块最高端 → 记录 Y 值
  5. 更新服务端代码中的 Y_MIN 和 Y_MAX

Q: 多个玩具同时用可以吗？

可以。方案一的 HTML 支持多设备同时连接（点扫描按钮可多次配对），每个设备独立 BLE 连接。方案二每次只能控制当前 APP 活跃的那一个设备（因为 ADB 触控是全局的）。如果两个方案并行，各自独立不冲突。
